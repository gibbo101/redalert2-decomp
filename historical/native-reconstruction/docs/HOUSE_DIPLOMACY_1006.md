## Ownership, scratch and effects

The context borrows three existing world views. Their callbacks must expose the
same canonical owners; the context creates no House, actor or target-registry
copies. Notification count/backing refer to the same variables as eligibility and
country lookup. MakeEnemy reads the same mask/flags/types/scores as MakeAlly.
The joined fixture reuses the existing MakeAlly ownership fixture, with a compile
switch for composition adapters; there is no second implementation of those
algorithms. The standalone fixture retains its original command/projection scope.

The context is immovable/noncopyable. It builds all closures before modifying
worlds, installs the three recursive call bindings and restores prior callbacks
on destruction, including exception unwinding. Missing scratch construction
refuses before installation. Native guard tests verify stable lifetime constraints,
normal restoration, failed construction and entered-session refusal restoration.
The caller must keep worlds/backing services alive for the context lifetime.

Every nested MakeAlly call owns a fresh caller token. Its initialization/padding
are supplied host setup; discarded nested stack bytes are not a fidelity claim.
The original executes each actual caller frame. Outer MakeAlly scratch retains
its earlier complete projection. For notification/MakeEnemy root tests, the
external unused fixture token is projected separately, not as original stack data.
The old diagnostic that directly writes the parent's fixed scratch is kept in
its standalone proof and excluded from this joined input domain; this does not
refuse a gameplay branch or narrow the recovered child algorithms.

Optional entry/store observers are nonmutating telemetry. Session virtual4,
map sight removal/addition, grid rebuild, localization/format/message/speech,
redraw, named virtual/weapon/release effects and initialization remain supplied.
A context is not a scheduler or original object-layout recovery. Exceptions retain
earlier kernel stores; callback restoration does not imply world rollback.
