## Existing owners

`Renderer::requestBuildingDraws` borrows the actual CellRedrawQueue+E0/embedded
identities, actual Tactical origin and existing frameDirtyRegions_ count/slots.
`BootCampVisibilityWorld::redrawCellPoint` resolves those identities against its
single canonical Cell table/shared fallback. No queue snapshot becomes the
production input, no new Cell registry/pixel buffer is introduced, and callbacks
are synchronous. Every clone must bind its own resolver and Building registry.

The actual-owner check queues a GI Cell through the existing recovered redraw
producer, centers on the real Building, and uses recovered invalidation to fill
the renderer's region queue. Requests then compose through the existing actual
Structure/Type/House/SHP/converter/depth owner path. It requires visible depth-bound
body writes, the aliased full request and preserved Cell count/slots/dirty byte,
all region entries/capacity tails, and source isolation. The existing clone after
source destruction still draws; a fresh cloned Cell resolver is also exercised.
These native checks remain separate from original expectation provenance.

Camera-derived viewport dimensions, explicit invocation, bypass/mode/startup and
other named downstream services retain their supplied boundaries. The parent
accepts up to800 live Cell slots/128 dirty regions as host safety bounds; the
actual projection adapter retains the existing +/-1,048,576-lepton domain.
Missing entered services or invalid backing refuse, and INT32_MIN dirty count
refuses its wrapped huge traversal. These are native safety limits, not recovered
original invalid-input behavior. No whole-frame fidelity or production frame/
sight/arrival/Objective1 scheduling is claimed.
